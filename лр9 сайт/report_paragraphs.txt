2.1. Создание локальной копии общего репозитория

2.2. Создание ветки

--- 85 style=normal
Для изоляции личных изменений от основной ветки main создайте новую ветку командой:

--- 86 style=normal
git checkout -b Bronnikova_branch

--- 87 style=normal
Команда одновременно создаёт ветку и переключает на неё рабочее окружение. Проверить переключение можно командой git branch — активная ветка будет отмечена звёздочкой *.

--- 99 style=Heading 2
2.4. Фиксация изменений (git add и git commit)

--- 100 style=normal
Добавьте файл в индекс подготовки командой:

--- 101 style=normal
git add Bronnikova_readme.txt

--- 102 style=normal
Зафиксируйте изменения в локальной истории:

--- 103 style=normal
git commit -m "Добавлен файл Bronnikova_readme.txt"

--- 104 style=normal
Терминал выведет информацию о созданном коммите (например, 1 file changed, X insertions(+)), что подтверждает успешную фиксацию.

--- 105 style=normal

Рисунок 6. Фиксация изменений командой git commit.

--- 106 style=Heading 2
2.5. Просмотр изменений (git diff)

--- 107 style=normal
Откройте Bronnikova_readme.txt, добавьте в конец строку, указывающую на готовность отчёта, и сохраните файл. Выполните команду:

--- 108 style=normal
git diff Bronnikova_readme.txt

--- 109 style=normal
Система сравнит текущую рабочую копию с последним коммитом и выведет различия. Добавленные строки будут отмечены символом + в начале.

--- 110 style=normal

Рисунок 7. Просмотр изменений командой git diff.

--- 111 style=Heading 2
2.6. Отправка изменений на сервер (git push)

--- 112 style=normal
Зафиксируйте внесённые правки:

--- 113 style=normal
git add Bronnikova_readme.txt

--- 114 style=normal
git commit -m "Добавлена информация о дате подготовки отчёта"

--- 115 style=normal
Отправьте ветку на удалённый сервер:

--- 116 style=normal
git push origin Bronnikova_branch

--- 117 style=normal
При запросе аутентификации используйте Personal Access Token вместо пароля от учётной записи. Команда синхронизирует локальную ветку с GitHub.

--- 118 style=normal
Рисунок 8. Синхронизация локальной ветки с удалённым репозиторием.

--- 119 style=Heading 2
2.7. Слияние веток (git merge)

--- 120 style=normal
Для отработки команды слияния создайте временную ветку:

--- 121 style=normal
git checkout -b test_merge

--- 122 style=normal
Добавьте в неё файл merge_demo.txt, выполните git add и git commit -m "Тестовый файл". Вернитесь в основную рабочую ветку:

--- 123 style=normal
git checkout Bronnikova_branch

--- 124 style=normal
Выполните слияние:

--- 125 style=normal
git merge test_merge

--- 126 style=normal
Система объединит истории двух веток. При успешном выполнении терминал выведет сообщение Merge made by the 'ort' strategy. без указания конфликтов.

--- 127 style=normal

Рисунок 9. Успешное слияние веток командой git merge.

--- 128 style=Heading 2
2.8. Перенос результатов в общий репозиторий

--- 129 style=normal
Так как прямой доступ на запись в общий репозиторий uasvistunova/ProfPO_ISTbd13 ограничен правами владельца, работа сдаётся через механизм форков. Создайте форк репозитория через веб-интерфейс GitHub. Добавьте его как удалённый источник в текущий проект:

--- 130 style=normal
git remote add fork https://github.com/pbronnikova/ProfPO_ISTbd13.git

--- 131 style=normal
Отправьте ветку в форк:

--- 132 style=normal
git push fork Bronnikova_branch

--- 133 style=normal
Результаты работы станут доступны преподавателю по ссылке на ваш форк.

Рисунок 10. Отправка ветки в форк общего репозитория.
