2.1. Создание локальной копии общего репозитория

--- 77
Для работы с общим репозиторием необходима его локальная копия на компьютере пользователя. В программе командной строки Git (терминал Git Bash, встроенный терминал VS Code или системная командная строка) сначала выполняется переход в каталог, где будет размещена копия (например, каталог на диске пользователя), затем выполняется клонирование по URL репозитория группы (процесс и результат показаны на рисунке 3).

--- 78
$ git clone https://github.com/uasvistunova/ProfPO_ISTbd13.git

--- 79
После выполнения команды git clone на диске создаётся папка ProfPO_ISTbd13 с файлами проекта и историей коммитов. Дальнейшие команды выполняются уже внутри этой папки; для перехода используется команда cd ProfPO_ISTbd13 (переход в локальную копию можно проверить по текущему пути в приглашении командной строки).

2.4. Фиксация изменений (git add и git commit)

--- 100
Файл включается в индекс для следующего коммита. В терминале Git выполняется команда:

--- 101
$ git add Bronnikova_readme.txt

--- 102
Изменения фиксируются в локальной истории командой:

--- 103
$ git commit -m "Добавлен файл Bronnikova_readme.txt"

--- 104
В терминале отображается краткий отчёт о коммите (например, 1 file changed, X insertions(+)), что подтверждает успешную фиксацию (рисунок 6).

--- 107

--- 108
$ git diff Bronnikova_readme.txt

--- 111
2.6. Отправка изменений на сервер (git push)

--- 112
Изменения снова добавляются в индекс и фиксируются коммитом, после чего выполняется отправка на GitHub.

--- 113
$ git add Bronnikova_readme.txt

--- 114
$ git commit -m "Добавлена информация о дате подготовки отчёта"

--- 115
Для отправки ветки на удалённый сервер в терминале выполняется команда git push с указанием ссылки origin и имени ветки (рисунок 8):

--- 116
$ git push origin Bronnikova_branch

--- 117
При запросе аутентификации на GitHub используется персональный токен (Personal Access Token) вместо пароля. После успешного выполнения локальная ветка синхронизируется с удалённым репозиторием командой git push.

--- 118
Рисунок 8. Синхронизация локальной ветки с удалённым репозиторием командой git push.

2.7. Слияние веток (git merge)

--- 120
Для отработки слияния создаётся временная ветка командой git checkout -b (новая ветка и переключение на неё):

--- 121
$ git checkout -b test_merge

--- 122
В этой ветке создаётся файл merge_demo.txt; выполняются индексация и коммит с сообщением «Тестовый файл». Затем выполняется возврат в основную ветку Bronnikova_branch и слияние.

--- 123
$ git checkout Bronnikova_branch

--- 124
Слияние временной ветки выполняется командой:

--- 125
$ git merge test_merge

--- 126
При отсутствии конфликтов выводится сообщение вида Merge made by the 'ort' strategy. (результат на рисунке 9).

--- 127
Рисунок 9. Успешное слияние веток командой git merge.

2.8. Перенос результатов в общий репозиторий

--- 129
Прямая запись в общий репозиторий uasvistunova/ProfPO_ISTbd13 ограничена правами владельца, поэтому результаты передаются через форк: на GitHub создаётся форк репозитория в свой аккаунт. В локальном проекте добавляется удалённый источник fork:

--- 130
$ git remote add fork https://github.com/pbronnikova/ProfPO_ISTbd13.githttps://github.com/pbronnikova/ProfPO_ISTbd13.git

--- 131
Ветка отправляется в форк командой git push:

--- 132
$ git push fork Bronnikova_branch

--- 133
После отправки в форк на GitHub оформляется pull request: ветка Bronnikova_branch предлагается к включению в репозиторий ProfPO_ISTbd13; после проверки изменения становятся доступны в общем проекте (иллюстрация — рисунок 10).
